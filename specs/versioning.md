# Guest ABI 与 API Level

包头的 ABI 大版本表示调用约定。删除导入、更改签名或改变既有调用的语义，需要新的 ABI 大版本。同一个 ABI 内，新增能力按递增的 API Level 登记。宿主和应用公开显示为 ABI 1.N，N 从 1 开始。

## 能力声明与加载

合同 `contracts/abi-v1.json` 记录每个导入、事件、输入掩码和权限的 `since_level`。新增能力提供可识别的新导入。SDK 取 Wasm 导入、应用声明的权限、应用显式要求的最低 Level 三者的最大值。只有需要新限额而没有新导入的应用必须显式声明。应用版本由作者单独递增。

| 条件 | 处理 |
|---|---|
| 包头偏移 184 为零 | 作为 Level 1 加载，Level 1 打包时继续写零 |
| ABI 大版本不符，或应用要求高于宿主 Level | 拒绝，提示所需固件版本 |
| 导入未知、声明低于导入或权限的引入 Level | 拒绝不一致的包 |
| 运行中硬件暂时不可用 | 支持该约定的新接口返回 -2，应用可以继续处理 |
| 应用没有接口要求的权限 | 按权限错误终止调用，既有导入维持原有行为 |

设备信息通过 BLE GET_DEVICE_INFO 和 USB INFO 报告 ABI 与 API Level。旧固件缺少字段时按 ABI 1、Level 1 解释。二进制 RUNTIME_INFO 的固定长度和布局保持兼容。每份面向 S31 的发布包携带 Wasm 和 AOT，设备执行 AOT。AOT 还必须匹配芯片目标与 compat_id。

## 发布

同一固件 minor 系列只发布修复，支持同一 Level。升级 Level 时按 core、固件、SDK 的顺序发布，三者分别递增 minor。只改 SDK 工具或文档可独立发 patch。首个支持各 Level 的固件及 AOT 世代登记在 SDK 的 `specs/compat-matrix.md`。对用户展示最低固件版本。同一系列后续发布的补丁继承原 Level。

Level 1 对应现有导入、触摸、时钟、运动和手柄。后续 Level 在对应能力完成并随正式固件发布后登记。同一 ABI 内固定 WAMR、LLVM、补丁和编译选项。若必须更换 AOT 世代，先准备网站从原 Wasm 批量复编译并按设备 compat_id 分发，对已安装应用提示更新，再登记新世代。

## 常见问题

- **固件上的 SDK 版本代表什么？** 它记录构建该固件时使用的 SDK。应用兼容性取决于设备的 ABI、Level 和 AOT 世代。
- **旧应用是否需要重打包？** Level 1 使用原来的零保留字段，可以继续使用已有兼容世代的包。
- **新版 SDK 能否给旧设备打包？** 可以。只使用旧能力、权限和限额时，SDK 记录对应的最低 Level。
