# TinyRT 宿主写入与坏包隔离语义

## KV 合并与持久化

`tinyrt_manager` 是单所有者同步组件。guest 的 `kv_set` 成功只表示宿主 RAM 已更新，随后 `kv_get` 立即可见；不表示数据已经落盘。guest ABI 和持久 KV 适配器接口均保持不变。

`TINYRT_MANAGER_SAVE_INTERVAL_MS` 为 5000。manager 生命周期中的第一次成功且改变 KV 的 init/event+render 可以立即保存；后续普通保存尝试相隔至少 5000 ms。manager 用同一个计时器覆盖所有 app，启动、切换、卸载或更新应用不会重置计时器。失败的保存尝试同样消耗本次普通保存机会，避免故障后重启形成密集重试。

每个成功 callback+render 都检查当前值是否与最近成功持久化的快照不同；不变时不写。到期时可由一个没有写 KV 的 callback 刷出先前累积的数据。因此等待期会合并多个写入；没有后续调度就不会自行保存。时钟由宿主 `now_ms` 提供，必须按 uint32_t 毫秒单调递增，允许自然回绕；计时使用无符号差值，宿主两次检查间隔须小于一个完整回绕周期。

正常 `stop` 的可选 guest 回调成功后，会强制刷出全部尚未保存的数据，包括先前 callback 积累的写入。保存更新同一个计时器，接下来的新实例仍需等待普通保存周期。正常退出是宿主控制的明确例外，不受 5 秒周期阻拦；重复由宿主触发退出/启动、关闭重建 manager、重启设备，均不在普通 callback 写入频率保证之内。guest 没有终止/启动管理接口。

guest 回调错误、陷阱、预算耗尽、render 错误或持久化失败会销毁实例并丢弃未持久化 RAM；故障实例不会再调用 stop。失败的 stop 同样丢弃积累数据。持久化错误保留错误状态和上一帧；底层 save 必须是事务式的，才能保证失败后原有持久值不变。`close` 尝试正常 stop 但没有返回状态；需要报告退出存档失败的宿主应先显式调用 `stop`。

正常周期性调度且保存成功时，断电可能丢失最近约 5 秒的数据；准确上限还包括下一次成功 callback 的调度延迟。没有调度、资源错误或存储故障时不承诺该上限。没有后台定时任务、guest 强制持久化 API、磁盘配额或包/KV 联合回滚。

内存成本为每个 manager 增加一份 16 个 i32 和有效位掩码的持久值快照，以及时间和状态字段；结构对齐后约 80 字节，不按事件分配内存。

## 最新目录和逐应用隔离

恢复先读取两个 `TRDIR001` 目录，仅根据格式、校验和、提交标记、记录结构和代数选择最新有效目录，再分别验证其包。最新目录中的一个包损坏不能让整个目录失效，不能因为旧包仍健康而退回旧版本，也不能恢复已卸载应用。目录结构本身损坏仍可能选到旧的有效目录；这与逻辑健康回滚不同。旧 `TRDIR001` 介质返回 `CORRUPT`，不自动格式化。

包返回 `VERIFY_FAILED`、`CORRUPT`，或验包所得身份/大小与目录不一致时，该条目在 RAM 中隔离。原目录记录、连续分配区间和 app ID 版本保留，仍占一个应用名额。健康列表排除隔离项；其他健康包照常列出、运行或更新。打开 manager 后新发现的包错误，会由 store 对照已提交身份再次验证，确认损坏后隔离并继续列出其余健康应用。运行实例存在时沿用其启动前验证过的目录缓存；不会抢占 WAMR 验证资源。

`IO_ERROR`、`NO_MEMORY`、`BUSY` 和验证器配置 `INVALID_ARGUMENT` 直接返回。它们不证明包损坏，不应隔离、删除或降级；恢复失败不发布部分 RAM 目录。恢复、隔离确认和诊断列表均不擦除或写入 Flash。

| API / 情形 | 结果 |
|---|---|
| `tinyrt_store_list` / `tinyrt_manager_list` | 只返回健康应用 |
| `tinyrt_store_list_quarantined` / `tinyrt_manager_list_quarantined` | 返回隔离应用的已提交完整身份和包长；不提供未经验证的标题 |
| exact identity `query` / `read` / manager `start` | 隔离项返回 `VERIFY_FAILED`；query 输出清零 |
| 过期版本或不同摘要的 query | `NOT_FOUND` |
| 安装完全相同身份、相同包长 | 隔离项允许写入独立暂存区间、完整验证后修复；健康项仍返回 `ALREADY_INSTALLED` |
| 相同 ID 更高版本 | 正常暂存、验证和提交，保留 KV；被隔离的旧条目仍保留到提交成功 |
| 相同 ID 更低版本、相同版本不同摘要或大小 | `CONFLICT` |
| 卸载隔离项 | manager 必须匹配完整已提交身份；store 以 app ID 移除目录，正常提交后释放名额 |
| `tinyrt_store_recheck` | 对精确已提交身份重新验证并更新 RAM 健康状态；不写介质，资源错误保留原健康状态 |

隔离状态是每次恢复重新计算的健康信息，不新增目录格式字段或持久隔离日志。每条 RAM 记录增加一个 bool 及对齐开销。`tinyrt_store_generation` / `tinyrt_manager_generation` 返回本次 store 生命周期内的 inventory revision；目录或隔离成员变化时增加，无变化的恢复保持不变。该标识独立于 Flash 目录代数，因此同数量但不同隔离成员也使跨页请求失效。详情见 [store format 1](store.md)。隔离不能自动恢复健康签名但逻辑错误的应用，也不提供数据迁移、旧版存档快照或自动降级。卸载后重新安装仍遵循现有清 KV 规则，不保留硬件防回滚版本高水位。

## 主机证据

Windows BCrypt 包测试使用两把真实 P-256 测试钥覆盖精确范围、点边界、跨发布者拒绝和不受限兼容。manager 测试使用显式 runtime 边界替身和真实 store，覆盖密集写入、到期时无写入 callback、回绕、保存失败、故障丢弃和启动/退出计时。集成测试使用真实签名及固定 WAMR，覆盖跨发布者升级失败、健康 app 与坏签名/坏载荷共存、运行后新发现损坏、原包修复、高版本替换和隔离卸载。store 保留现有断电写入矩阵，并测试最新目录、旧版本不复活及资源错误不改变健康状态。

这些测试不替代实机 NVS 耐久性、随机物理断电或量产信任配置验收。
